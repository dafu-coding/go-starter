# Launchboard ↗

**チームの仕事を、前へ。** Go + PostgreSQL で動く、小さなチーム向けのタスク管理アプリです。

## 毎日の仕事に使える機能

- **作成・編集**：タイトル、3000文字までのメモ、担当者、期限、優先度、カテゴリ
- **進捗管理**：未着手 → 進行中 → 完了。ボードとリストを切り替え
- **見落とし防止**：期限切れ・今日の期限を表示。「自分の担当」「今日までの期限」ですぐ絞り込み
- **検索**：タイトル・メモ・担当者で検索。カテゴリ、担当、優先度での絞り込みと並び替え
- **整理**：アーカイブ、復元、直後の「元に戻す」。完全削除はしません
- **CSV出力**：アーカイブを含む全タスクをUTF-8 BOM付きCSVに保存。数式として解釈されるセルをエスケープ
- **共有パスワード**：`APP_PASSWORD` を設定すると、ログイン後だけタスクの閲覧・更新・CSV出力が可能
- **更新の保護**：バージョン番号で同時編集を検出。古い内容からの保存は409を返して上書きを防止
- **下書き保存**：新規タスクの入力はブラウザに保存。作成成功時にクリア
- PC・スマートフォン対応。30秒ごとの更新と手動更新

## 使い始める

1. タスクを追加し、担当者と期限を決めます。タイトルだけでも作成できます。
2. 左下の表示名を設定すると、「自分の担当」に同じ名前のタスクが表示されます。
3. カードのタイトルをクリックして編集。下部のステータスで進捗を更新します。
4. 不要になったタスクはアーカイブへ。保管一覧からいつでも復元できます。

新しいDBは空の状態から始まります。「サンプルで試す」を押すと6件のタスクを追加できます。サンプルはまとめてアーカイブでき、実タスクは残ります。

## Kamui へのデプロイ

GitHub の `dafu-coding/go-starter`、ブランチ `main` を選び、PostgreSQL を接続してください。`DATABASE_URL` は Kamui から自動設定されます。

| 項目 | 設定 |
| --- | --- |
| Setup Command | `go build -trimpath -ldflags='-s -w' -o out/app ./cmd/server && go build -trimpath -ldflags='-s -w' -o out/db ./cmd/db` |
| Pre-deploy Command | `out/db` |
| Start Command | `out/app` |
| Health Check Path | `/health` |

### 環境変数

| 変数 | 用途 |
| --- | --- |
| `DATABASE_URL` | 必須。標準のPostgreSQL接続URLをそのまま使用 |
| `PORT` | Kamuiから設定。ローカル既定値 `8000` |
| `APP_PASSWORD` | 任意。12文字以上の共有パスワード。実際のチーム利用では設定してください |

`APP_PASSWORD` はダッシュボードの安全な環境変数設定から登録してください。チャットやGitにパスワードを載せる必要はありません。未設定なら、URLを知っている人全員が閲覧・編集できる公開ワークスペースになります。

ログインセッションは7日間。HttpOnly・SameSite=Strict、HTTPS時はSecure属性を使用します。パスワード変更後は既存セッションが無効になります。同じパスワードを使う全員が同じ権限を持ち、個人アカウント・管理者権限・監査ログ・ユーザー別データ分離はありません。表示名は担当者フィルター用で、本人認証ではありません。ログイン試行制限はプロセス単位・接続元IP単位です。

`/health` はログイン不要でDBの疎通を返します。DB接続には接続先に応じたTLS設定を使用してください。DB未接続時は起動に失敗します。

## 永続化と既存版からの更新

データはPostgreSQLに保存され、再起動しても維持されます。サーバー起動時にもマイグレーションを実行し、複数レプリカの同時起動はadvisory lockで直列化します。静的アセットとSQLはバイナリへ埋め込みます。

以前のLaunchboardからの更新では、既存の投稿・ステータス・実投票を保持したまま担当・期限などの列を追加します。既存レコードは担当未割り当て、優先度通常、期限なしとして表示します。旧版の仮の投票数は表示しません。サンプルの自動再追加を停止し、起動時にユーザーデータを初期化しません。スターターの `greetings` テーブルも保持します。

内部のテーブル名 `launchboard_ideas` と既存投票APIは互換性のため保持しています。タスク更新APIには現在の `version` が必要です。旧版クライアントはページを再読み込みしてください。

CSVはバックアップや表計算ソフトでの利用向けです。CSVインポートは実装していません。ワークスペースはDBごとに1つです。

## ローカル起動

Go 1.23以降とPostgreSQLを用意してください。

```sh
export DATABASE_URL='postgres://localhost:5432/launchboard?sslmode=disable'
go run ./cmd/db
go run ./cmd/server
```

[http://localhost:8000](http://localhost:8000) を開きます。`.env.example` は設定例で、自動読み込みはしません。

## 検証

```sh
go test ./...
go vet ./...
node --check cmd/server/static/app.js
```

DB統合テストは専用の使い捨てローカルDBで、毎回隔離スキーマを作って実行します。

```sh
createdb -h 127.0.0.1 -p 55439 -U launchboard launchboard_test
TEST_DATABASE_URL='postgres://launchboard@127.0.0.1:55439/launchboard_test?sslmode=disable' go test -race -v ./...
```

空の初期状態、任意のサンプル追加、編集と期限クリア、同時更新の拒否、アーカイブと復元、再接続後の永続化、CSVの数式対策、入力検証、別Originからの書き込み拒否、パスワード保護、Cookie改ざん拒否、パスワード変更後の失効、ログイン試行制限を確認します。`TEST_DATABASE_URL` 未設定時はDB統合テストをスキップします。
